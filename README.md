# session-map-mods

**모든 Claude Code 세션이 함께 쓰는 세션 맵을 한 패널에 보여 주는 mod.**

세션마다 제목·목적·지금 상태·상위 세션·다룬 이슈와 PR 을 공유 폴더에 기록한다. 세션은 요청마다 다른 세션 목록을 받아 서로를 안다. `/session-map` 으로 패널을 열면 섹션 목록·작업 목록·타임라인으로 모든 세션을 본다.

## 무엇을 해결하는가

세션이 많아지면 다음을 잃어버린다.

- **세션이 하는 일** — 어떤 세션이 지금 무슨 일을 하는지 모른다.
- **세션이 속한 작업** — 여러 섹션에 걸친 큰 작업에 어떤 세션이 들어 있는지 모른다.
- **세션이 갈라진 곳** — 어느 세션에서 시작했거나 곁가지로 나왔는지 모른다.

모든 세션이 같은 세션 맵을 읽고 쓰게 해, 이것을 한 패널에서 보여 준다.

## 동작 방식

### 기록

세션마다 자기 파일 하나만 쓴다. 두 세션이 같은 파일을 쓰지 않으므로 동시 쓰기 충돌이 없다.

```text
~/.claude/session-map/
└── <세션 id>.json    제목, 목적, 지금 상태, 상위 세션, 곁가지 세션, 이슈·PR, 저장소, 폴더, 시각, 상태
```

시험할 때는 환경 변수 `SESSION_MAP_DIR` 로 다른 폴더를 쓴다. 세션은 1분마다 자기 파일의 마지막 시각을 고친다. 마지막 신호가 10분보다 오래된 진행 중 기록은 「응답 없음」으로 본다.

| 기록 | 언제 적는가 |
| --- | --- |
| 지금 상태 | 턴을 마칠 때 남기는 요약(`mcp__ccd_turn__wrap_up` 의 recap)을 적는다 |
| 저장소 | `git`·`gh` 명령을 실행한 폴더의 `origin` 이 GitHub 저장소이면 `owner/name` 을 적는다 |
| 이슈·PR | `gh issue`·`gh pr` 쓰기 명령(create, close, merge, comment 등)이 다룬 번호를 적는다. `view`·`list`·`status`·`diff`·`checks` 는 읽기라서 적지 않는다 |
| 제목·목적·관계 | `register_session` 도구로 적는다 |

### 데스크톱 앱 목록 읽기

데스크톱 앱의 사이드바 섹션과 세션 목록을 읽어 기록과 합친다. 세션을 한 번에 많이 읽으면 도구 결과가 크기 한도를 넘는다(200개에 약 10만 자). 그래서 사이드바 그룹마다 따로 최대 100개를 읽고, 그룹 없는 세션은 최근 40개만 읽는다. 목록은 3분마다 다시 읽는다.

### 세션끼리 알기

요청마다 최근 24시간에 활동한 다른 세션을 최대 15개까지 컨텍스트로 붙인다. 각 줄에는 상태, 제목, 지금 상태(없으면 목적), 세션 id, 폴더, 상위 세션이 있다. 같은 컨텍스트에 `register_session` 도구를 쓰는 규칙도 붙인다.

### `register_session` 도구

바꿀 필드만 보낸다.

| 입력 | 뜻 |
| --- | --- |
| `title` | 세션 제목, 짧은 명사구 |
| `purpose` | 이 세션이 처리하려는 일, 한 문장 |
| `parentId` | 상위 세션 id. 지시문에 「상위 세션 id」가 있을 때만 보낸다 |
| `relatedId` | 이 작업이 속하거나 곁가지로 나온 다른 세션 id. 사용자가 그렇다고 말했을 때만 보낸다. 보낼 때마다 하나씩 더한다 |

## 패널

`/session-map` 으로 연다. 패널은 최근 30일에 활동한 세션을 보여 준다.

### 탭

| 탭 | 보여 주는 것 |
| --- | --- |
| 섹션 목록 | 사이드바와 같은 순서의 섹션. 사이드바에 없는 섹션(터미널 세션의 폴더 이름)은 뒤에 둔다. 섹션 안의 세션은 시작 관계 트리(`├─▶`, `└─▶`)로 보여 준다. 섹션과 트리는 `▾`/`▸` 로 접고 편다. 개수와 시각은 보여 주지 않는다 |
| 작업 목록 | 큰 작업 목록, 최신순. 작업마다 섹션 이름과 이슈·PR 을 보여 준다. 작업을 누르면 작업 화면이 열린다 |
| 타임라인 | 마지막 활동 날짜별(「오늘」, 「어제」, 「10월 21일 (수)」) 세션 목록, 최신순. 줄마다 시각, 섹션·작업 이름, 지금 상태를 보여 준다 |

섹션 목록에서 섹션은 사이드바에서 접혀 있으면 접힌 채로 시작하고, 트리는 진행 중인 하위 세션이 있는 항목만 펼친 채로 시작한다. 작업 화면의 트리는 모두 펼친 채로 시작한다. btw 곁질문과 사이드 채팅은 처음에 숨긴다.

### 작업 묶기

다음 중 하나라도 맞으면 두 세션을 같은 작업으로 묶는다.

- 한 세션이 다른 세션을 시작했다. 섹션이 달라도 묶는다.
- `relatedId` 로 곁가지를 이어 두었다.
- 같은 저장소의 같은 이슈·PR 을 다뤘다. 세션 제목에서만 읽은 번호는 같은 섹션·같은 폴더일 때만 묶는다.
- 같은 섹션에서 같은 저장소를 다뤘다.

작업의 출발점은 작업 안에서 상위 세션이 없는 세션 중 가장 먼저 시작한 세션이다. 작업 이름은 출발점 제목에서 `[완료]`, `#12` 같은 앞머리를 뺀 것이다.

### 작업 화면

| 부분 | 보여 주는 것 |
| --- | --- |
| 트리 | 작업 안 세션의 시작 관계 트리. 출발점을 뺀 하위 세션이 5개 이상이면 모델이 하는 일별로 2~6개 묶음으로 나누고, 묶음마다 트리를 보여 준다 |
| 플로우 그림 | 시작한 세션을 왼쪽, 시작된 세션을 오른쪽에 둔 SVG 그림. 칸마다 상태, 지금 상태, 이슈·PR 을 보여 준다. 처음에는 접혀 있다(`▸ 플로우 그림`) |
| 연관 세션 | 작업 밖이지만 함께 볼 세션 최대 8개와 이유. 이유는 「같은 번호 #N」, 「같은 저장소 owner/name」, 「같은 섹션·같은 기간」 순서로 보여 준다 |

`◀ 작업 목록` 을 누르면 작업 목록으로 돌아간다.

### 정렬과 필터

섹션 목록·작업 목록·타임라인 위에 있다. 작업 화면에는 없다.

| 항목 | 값 |
| --- | --- |
| 정렬 | 최근 활동, 시작 순서, 이름, 상태. 작업 목록은 이름과 시작 순서만 따로 정렬하고, 나머지는 최근 활동 순서다 |
| 상태 | 전체, 진행 중, 대기(응답 없음 포함), 완료 |
| 기간 | 전체, 오늘, 7일 |
| 곁질문 보기 | 켜면 btw 곁질문과 사이드 채팅을 보여 준다 |
| 검색 | 제목·목적·지금 상태·섹션 이름에서 찾는다 |

필터에 맞지 않는 세션도 맞는 하위 세션이 있으면 남겨 트리를 끊지 않는다.

### 상태 표시

| 표시 | 상태 | 뜻 |
| --- | --- | --- |
| ● | 진행 중 | 데스크톱 앱에서 답을 만드는 중이거나, 최근 10분 안에 기록이 신호를 보냈다 |
| ○ | 대기 | 열려 있지만 지금 일하지 않는다 |
| ◌ | 응답 없음 | 기록은 진행 중인데 10분 넘게 신호가 없고 데스크톱 목록에도 없다 |
| ✓ | 완료 | PR 이 머지됐거나 제목이 `[완료]` 로 시작한다. 데스크톱 목록에 없는 세션은 기록이 끝났을 때다 |

### 세션 이동

세션 제목을 누르면 `claude://` 링크로 그 세션을 연다. 데스크톱 앱 세션이 아니면 열 수 없다는 알림을 보여 준다.

### 화면별 차이

| 화면 | 차이 |
| --- | --- |
| 데스크톱 앱 | 글자 트리와 플로우 그림(SVG)을 보여 준다 |
| 터미널 | 같은 글자 트리를 보여 주고, 플로우 그림은 없다 |

## 설치

### 설치

GitHub 저장소 `insung/session-map-mods` 를 marketplace 로 추가하고 user scope 에 설치한다.

```bash
claude plugin marketplace add insung/session-map-mods
```

```bash
claude plugin install session-map@session-map-mods --scope user
```

설치한 뒤 새로 시작한 세션부터 로드된다.

### 갱신

새 버전이 `main` 에 올라오면 아래 두 명령을 실행한다. `.claude-plugin/plugin.json` 의 `version` 이 같으면 갱신하지 않을 수 있다.

```bash
claude plugin marketplace update session-map-mods
```

```bash
claude plugin update session-map@session-map-mods
```

새 세션을 열고 `/session-map` 으로 확인한다.

### 제거

```bash
claude plugin uninstall session-map@session-map-mods
```

## 외부 호출

| 호출 | 언제 | 보내는 내용 | 이유 |
| --- | --- | --- | --- |
| 데스크톱 앱 도구 `mcp__ccd_sidebar__list_sections` | 세션 시작, 3분마다, `/session-map` | 없음 | 사이드바 섹션과 순서를 읽는다 |
| 데스크톱 앱 도구 `mcp__ccd_session_mgmt__list_sessions` | 위와 같음 | 그룹 id, 개수 한도 | 그룹마다 세션 목록을 읽는다 |
| 데스크톱 앱 도구 `mcp__ccd_session_mgmt__get_session` | 위와 같음 | `self` | 세션 목록에 빠진 이 세션을 읽는다 |
| 모델 호출 (`haiku`) | 하위 세션이 5개 이상인 작업을 처음 열 때, 작업의 세션 구성이 바뀐 뒤 열 때 | 세션 id, 제목, 목적, 지금 상태 앞 120자 | 하위 세션을 하는 일별로 묶는다. 결과는 저장해 두고 구성이 같으면 다시 묻지 않는다 |
| `open <claude:// 링크>` | 세션 제목을 누를 때 | 세션 링크 | 그 세션을 연다 |
| `git -C <폴더> remote get-url origin` | `git`·`gh` 명령을 실행한 뒤 | 없음 | 명령을 실행한 폴더의 GitHub 저장소를 안다 |

데스크톱 앱 도구를 부를 수 없는 세션(터미널 세션)은 공유 폴더 기록만으로 패널을 그린다.

## 한계

- **설치 전 세션** — 설치하기 전에 시작한 세션은 기록이 없어 목적·지금 상태·이슈·PR·저장소를 모른다. 데스크톱 앱 목록에서 읽은 제목, 시작 관계, 데스크톱 앱이 아는 PR 만 보인다.
- **이슈·PR 상태** — 이 mod 가 기록한 세션에서 `gh` 명령으로 바꾼 상태와, 데스크톱 앱이 알려 주는 세션 PR 의 상태만 안다. 그 밖에 GitHub 화면이나 다른 도구에서 닫거나 머지한 것은 모른다.
- **제목에서 읽은 번호** — 세션 제목의 `#12` 는 저장소를 모른다. 그래서 같은 섹션·같은 폴더일 때만 같은 작업으로 묶는다.
- **btw 판별** — btw 곁질문과 사이드 채팅은 제목(`btw:` 로 시작, 또는 「사이드 채팅」)으로만 알아본다.

## 구조

```text
.claude-plugin/
├── plugin.json        mod 이름, 버전, 타입 파일
└── marketplace.json   marketplace 정의 (저장소 루트를 mod 로 제공)
hooks/
├── hooks.json         로드할 모듈 (register.tsx)
├── register.tsx       세션 기록, 컨텍스트, register_session 도구, /session-map 명령, 패널
├── graph.ts           기록과 데스크톱 목록 합치기, 상태, 작업 묶기, 트리, 타임라인, 정렬·필터
├── host.ts            데스크톱 앱 섹션·세션 목록 읽기, btw 판별
├── flow.ts            플로우 그림 배치와 SVG
├── views.tsx          탭·작업 화면·정렬·필터 화면
├── labels.ts          모델로 하위 세션을 하는 일별로 묶기
└── refs.ts            gh 명령·세션 제목에서 이슈·PR 읽기, git remote 에서 저장소 읽기
types/
└── index.d.ts         기록·화면 타입, mod 상태 타입
tests/
├── fixtures.ts        시험용 세션 기록과 데스크톱 목록
├── graph.test.ts      작업 묶기·트리·타임라인·플로우·이슈 읽기 시험
└── session-map.test.tsx  패널 탭과 데스크톱 목록 읽기 시험
```

mod 정의를 검사한다.


시험을 실행한다.

```bash

```

## 브랜치 전략

GitHub Flow 를 따른다. 이 절이 이 저장소의 브랜치 전략 정본이다.

| 구분 | 규칙 |
| --- | --- |
| 일반 작업 | 최신 `main` 에서 `<type>/<주제>` 브랜치를 만든다 (예: `feat/task-tab`). 워크트리는 `.worktree/<type>-<주제>` 에 둔다. PR 대상은 `main` 이고 Merge commit 으로 머지한다. `main` 에 직접 push 하지 않는다. |
| 긴급 수정 | 운영 브랜치가 따로 없다. 일반 작업과 같이 `main` → `fix/<주제>` → `main` PR 로 처리한다. |
| 배포 | GitHub 저장소가 marketplace 다. `main` 에 머지되고 `version` 이 올라가면, 사용자는 `claude plugin marketplace update`·`claude plugin update` 로 새 버전을 받는다. 릴리즈할 때 `.claude-plugin/plugin.json` 의 `version` 을 올린 `main` 커밋에 `vX.Y.Z` 태그를 붙인다. 롤백은 되돌리는 커밋을 PR 로 머지한다. |
| 미정·충돌 | 이 절과 다른 지시가 있거나 정하지 않은 항목이 있으면 브랜치 생성·PR·머지 전에 확인한다. |

## 마일스톤

| 항목 | 기준 |
| --- | --- |
| 이름 | `vX.Y.Z`. `plugin.json` 의 `version`, git 태그와 같다. |
| 연결 | Issue 를 마일스톤에 연결한다. PR 은 연결한 Issue 로 추적한다. |
| 기한 | 출시일을 합의한 경우에만 정한다. |
| 발행 | 마일스톤의 Issue 가 모두 닫히고 `version` 과 태그가 같으면 Release 를 발행한다. |
| 종료 | Release 발행을 확인하고 사용자가 승인하면 닫는다. |
